## Po co nam baza danych?

Najprościej mówiąc: baza danych to kontener, w którym przechowujemy informacje o użytkownikach, filmach i innych obiektach aplikacji.

W tym konspekcie zaczniemy od modelu przeznaczonego do przechowywania filmów.

## "Klasyczne" zarządzanie bazami danych

Bez frameworka, taka praca zwykle wymaga ręcznego pisania SQL.

Przykładowe tworzenie tabeli:

```sql
CREATE TABLE movies (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    description TEXT,
    premiere_date DATE
);
```

---

## "Klasyczne" zarządzanie bazami danych

Taki kod trzeba potem:

- testować,
- zapisać i wersjonować,
- uruchamiać w odpowiednim momencie na właściwej bazie.

To jest bardziej podatne na pomyłki i bardziej czasochłonne.

---

## Tworzenie tabeli w Django

W Django opisujemy strukturę tabeli jako klasę w `movies/models.py`.

```bash
nano movies/models.py
```

---

## Tworzenie tabeli w Django

Przykładowa definicja modelu `Movie`:

```python
from django.db import models


class Movie(models.Model):
    title = models.CharField(max_length=200)
    description = models.TextField(blank=True)
    premiere_date = models.DateField(null=True, blank=True)

    def __str__(self):
        return self.title
```

---

## Podgląd migracji

Jeśli chcemy najpierw podejrzeć, co Django wygeneruje, możemy uruchomić:

```bash
python manage.py makemigrations --dry-run --verbosity 3
```

To wykonanie "na sucho" — migracja nie zostanie zapisana, ale zobaczymy plan zmian.

---

## Migracja

Generujemy migrację:

```bash
python manage.py makemigrations
```

Po tym kroku pojawi się plik typu `movies/migrations/0001_initial.py`.

W nagłówku takiego pliku zobaczysz komentarz `# Generated by Django ...`.

---

## Migracja

Dla potwierdzenia możemy sprawdzić katalog migracji:

```bash
ls -alh movies/migrations
```

Migracje są automatycznie numerowane.

---

## Aplikowanie migracji

Teraz trzeba zaaplikować migrację do bazy danych:

```bash
python manage.py migrate
```

W wyniku zobaczymy linię z `Applying movies... OK`.

---

## Podsumowanie migracji

Aby przechowywać dane w bazie danych:

1. Opisujemy model w `models.py`.
2. Generujemy migrację (`makemigrations`).
3. Aplikujemy migrację (`migrate`).

## Podgląd tabel SQLite

Nie musimy instalować osobnego programu do oglądania pliku `db.sqlite3`.

Jeśli chcemy zobaczyć surowe tabele w pliku SQLite, możemy użyć modułu `sqlite3` dostarczanego z Pythonem:

```bash
python -m sqlite3 db.sqlite3 "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;"
```

Po migracji powinniśmy zobaczyć między innymi tabelę `movies_movie`.

---

## Podgląd rekordów SQLite

Możemy też odpytać tabelę z filmami:

```bash
python -m sqlite3 db.sqlite3 "SELECT id, title, premiere_date FROM movies_movie;"
```

Na tym etapie wynik może być pusty, bo utworzyliśmy tabelę, ale nie dodaliśmy jeszcze żadnych filmów.

Pusty wynik nie oznacza błędu. Oznacza tylko, że tabela nie ma jeszcze rekordów.

## Panel administracyjny

Najszybszy sposób dodawania rekordów na tym etapie to panel admin.

Aby model `Movie` był widoczny w panelu, rejestrujemy go w `movies/admin.py`.

Domyślnie w tym pliku zobaczysz komentarz `# Register your models here`.

```bash
nano movies/admin.py
```

---

## Panel administracyjny

Dodajemy kod:

```python

from .models import Movie

admin.site.register(Movie)
```

## Podgląd danych przez Django

Po dodaniu filmów możemy sprawdzić dane bezpośrednio z terminala:

```bash
python manage.py shell -c "from movies.models import Movie; print(list(Movie.objects.values('id', 'title', 'description', 'premiere_date')))"
```

Django może najpierw wypisać komunikat typu `13 objects imported automatically`. Interesuje nas ostatnia linia z listą filmów.

Jeśli nadal widzimy `[]`, to znaczy, że w tej bazie nie ma jeszcze żadnych filmów albo dodaliśmy je w innym katalogu projektu.

## Szablony HTML w Django - szablon bazowy dla naszej aplikacji

W wielu stronach powtarzają się elementy typu nagłówek, menu, stopka.

Django daje na to mechanizm dziedziczenia szablonów (`{% extends %}`, `{% block %}`).

---

## Szablon bazowy dla naszej aplikacji

Tworzymy plik bazowy:

```bash
nano movies/templates/base.html
```

---

## Szablon bazowy dla naszej aplikacji

Początkowa zawartość `base.html`:

```html
<!doctype html>
<html lang="pl">
  <head>
    <meta charset="utf-8" />
    <title>Moja biblioteka filmów</title>
  </head>
  <body>
    <h1>Moja biblioteka filmów</h1>
    {% block content %}{% endblock %}
  </body>
</html>
```

---

## Szablony HTML w Django - szablon bazowy dla naszej aplikacji

Mamy już gotowy szablon bazowy.

Za chwilę przebudujemy `hello.html` tak, żeby jednocześnie:

- korzystał z `base.html`,
- wyświetlał dane pobrane z bazy.

---

## Prezentacja danych z bazy

W widoku pobieramy dane i przekazujemy je do szablonu:

```bash
nano movies/views.py
```

```python
from django.shortcuts import render

from .models import Movie


def hello_world(request):
    movies = Movie.objects.all()
    return render(request, "hello.html", {"movies": movies})
```

---

## Prezentacja danych z bazy

Teraz przebudowujemy szablon `hello.html`:

```bash
nano movies/templates/hello.html
```

Zastępujemy całą dotychczasową zawartość pliku wersją, która korzysta z `base.html` i wyświetla listę filmów:

```django
{% extends "base.html" %}

{% block content %}
  <ul>
    {% for movie in movies %}
      <li>{{ movie.title }}</li>
    {% endfor %}
  </ul>
{% endblock %}
```

Spróbujmy odświeżyć stronę [http://127.0.0.1:8000/hello/](http://127.0.0.1:8000/hello/).

## Zadanie

Sprawdź, czy użytkownik jest uwierzytelniony.

Można wykorzystać informacje o użytkowniku z obiektu `request` i wypisać je w szablonie.

Przykładowo użyj `{{ request.user }}` lub `{{ request.user.is_authenticated }}` i sprawdź wynik przed oraz po zalogowaniu.

---

## Rozwiązanie

W `movies/templates/hello.html`, wewnątrz bloku `{% block content %}`, można dopisać:

```django
<p>
  Użytkownik: {{ request.user }}
</p>
<p>
  Czy zalogowany: {{ request.user.is_authenticated }}
</p>
```

Przed zalogowaniem zobaczymy zwykle `AnonymousUser` i `False`. Po zalogowaniu przez panel admina zobaczymy nazwę użytkownika i `True`.
